# Face Access: распознавание лиц для турникета (ArcFace + FastAPI + MediaMTX)

Камера (RTSP) -> распознавание ArcFace на GPU -> открытие турникета через API.
Картинка с рамками и подписями публикуется в MediaMTX (кодирование на GPU, NVENC) и показывается на веб-странице.
Веб-страница нужна для настройки и для добавления фото сотрудников (в т.ч. с веб-камеры компьютера, с которого она открыта).

## Структура
```
run.py                 запуск (веб + распознавание), а также --encode и --list
main.py                FastAPI: страница, настройки, фото, прокси WebRTC-просмотра
configs/config.yaml     настройки программы (сервис читает только его)
configs/mediamtx.yml    настройки MediaMTX (mediamtx.service запускает его с этим файлом)
templates/camera.html  веб-страница
src/service.py         основной цикл: камера -> движок -> турникет -> стрим
src/camera.py          чтение RTSP (свежий кадр, автопереподключение), зоны турникета, рамки/подписи
src/streamer.py        ffmpeg -> MediaMTX (NVENC / x264)
src/utils.py           API турникета, список пользователей (db | excel), лог
src/engines/           движки распознавания (сейчас только arcface)
```

## Установка и запуск
```bash
sudo apt install -y python3-dev build-essential fonts-dejavu-core
pip install -r requirements.txt
python3 check_gpu.py            # проверка GPU (если есть)
python3 run.py -p <пароль_API> --encode  # эмбеддинги для фото из images/ (имя файла = id сотрудника)
python3 run.py -p <пароль_API>          # пароль API (connection.password) задаётся при запуске, остальные настройки - в configs/config.yaml; https://<адрес-сервера>:8000
```
Пароль API можно передать и через переменную окружения `FACE_API_PASSWORD` (удобно для systemd: `Environment=FACE_API_PASSWORD=...`),
тогда в config.yaml его хранить не нужно. Без `-p` используется `connection.password` из config.yaml (для совместимости со старыми конфигами).
Автозапуск: `mediamtx.service` и `face-access.service` (пути в них - /faceId) -> `systemctl enable --now mediamtx face-access`.

## Веб-страница
* **Видео** - поток из MediaMTX по WebRTC (страница общается с MediaMTX через сервер, поэтому порт 8889 снаружи не нужен;
  медиа идёт напрямую на UDP 8189 MediaMTX - он должен быть доступен с компьютера, где открыта страница).
* **Добавить фото** - выбрать сотрудника, включить веб-камеру браузера (нужен HTTPS или localhost), снять, отправить.
  Сервер проверяет, что на фото есть лицо, сохраняет `images/<id>.jpg` (старое уходит в `images/_archive`), считает эмбеддинг
  и сразу начинает распознавать. Можно загрузить и готовый файл.
* **Включить проход по лицу** - для выбранного сотрудника: эмбеддинг по фото (имя файла = id) + отметка в Perco (так сотрудник попадает в число тех, кого распознаёт камера). **Убрать проход по лицу** - фото и эмбеддинг уходят в архив (`images/_archive`, `<эмбеддинги>/_archive`), отметка в Perco снимается. Особенности Perco описаны только в `src/utils.py`.
* **Переключатель «показывать»** над видео включает/выключает картинку с IP-камеры (когда выключено, соединение с MediaMTX закрыто).
* **Настройки** - конфиг редактируется прямо на странице (или загружается файлом); перед применением проверяется; при ошибке остаётся прежний конфиг, копия старого - `config.yaml.bak`);
  «Синхронизировать» - перечитывает сотрудников (БД/Excel) и считает эмбеддинги для новых фото без перезапуска камеры.
* Доступ к странице ограничивается списком `web.allowed_ips`. Пароль для входа - следующий этап.

## Вход в веб-интерфейс
Логин и пароль проверяет **Perco**: данные из формы отправляются в Perco тем же запросом, которым программа входит в Perco
(`/api/system/auth`). Выдал токен - человек вошёл. Паролей в нашем конфиге нет, токен не сохраняется.
* `auth.allowed_logins` - какие учётные записи Perco пускать (пусто = любую, которую примет Perco; на странице можно менять конфиг,
  поэтому лучше перечислить нужные).
* Аварийный вход: необязательные `auth.users` (с `password_hash`) действуют **только пока Perco недоступен**.
* `auth.provider: local` - пользователи из `auth.users` (для установок без Perco).
* Сессия живёт в памяти (`session_hours`) и сбрасывается при перезапуске. После `max_attempts` неудач с одного IP или
  `max_attempts_per_login` неудач для одного логина вход блокируется на `lockout_minutes`.
* Пока раздела `auth` нет, веб закрыт целиком, а распознавание и турникет работают. Отключить вход можно только явно: `auth.enabled: false`.
* Из браузера нельзя применить конфиг, после которого вы сами потеряете доступ.
* Кука сессии: HttpOnly, SameSite=Strict, Secure по HTTPS. Автодокументация FastAPI (`/docs`) отключена.

## Как добавить другой движок распознавания
1. `src/engines/<имя>.py`: класс-наследник `FaceEngine`, реализовать `load_model()`, `encode_image()`, `detect_faces()` (подробно - в `src/engines/base.py`).
2. Одна строка в `_ENGINES` в `src/engines/__init__.py`.
3. В `config.yaml`: `mode: <имя>` и раздел `<имя>:` с `embedding_folder` и `threshold`.

Хранение эмбеддингов, кодирование папки с фото, добавление фото и сопоставление уже реализованы в базовом классе.

## MediaMTX
Путь из `rtsp_server.url` (например, `test`) должен быть описан в `paths:` в `mediamtx.yml`; WebRTC (`webrtc: yes`) включён;
запросы сервера на просмотр приходят с 127.0.0.1 - этот адрес должен быть в списке `read` в `authInternalUsers`.
