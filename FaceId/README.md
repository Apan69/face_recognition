# Face Access: проход по лицу + Perco

Программа открывает турникет по лицу сотрудника и показывает на веб-странице, кто и когда входил и выходил.
Лица распознаёт камера (RTSP или USB), список сотрудников и права берутся из системы допуска **Perco**,
турникетом управляет Perco (через его API), а видео с разметкой публикуется в **MediaMTX** и смотрится в браузере по WebRTC.

Всё работает одним процессом: `run.py` запускает веб-сервер (FastAPI + uvicorn), а он запускает распознавание в фоновых потоках.

## Что умеет

- **Распознавание лиц** (ArcFace через insightface, модели `buffalo_l` / `buffalo_s`): камера видит лицо в зоне турникета, сравнивает с базой эмбеддингов и открывает турникет на вход или на выход.
- **Две зоны в кадре**: «Выход» и «Вход». Куда встал человек, в ту сторону и открывается турникет.
- **Список сотрудников из Perco** (или из Excel). По лицу проходят только те, у кого в Perco включена отметка «проход по лицу».
- **Управление проходом по лицу с веб-страницы**: сделать фото (веб-камерой браузера или файлом), посчитать эмбеддинг, включить или убрать проход.
- **Журнал проходов всех людей** из журнала событий Perco: по картам, по лицу и по кнопке вахтёра, с направлением (вход/выход), подразделением и способом.
- **Кто сейчас в здании**: отдельный режим просмотра и оценка общего числа с учётом проходов по кнопке.
- **Фильтры** проходов по фамилии и подразделению, крупная строка «последний вошедший/вышедший».
- **Видео в браузере** с разметкой зон и подписями лиц (WebRTC через MediaMTX).
- **Вход на страницу по учётной записи Perco** с ролями (три уровня доступа, три вкладки).
- **Просмотр log.txt** на самой странице и редактирование `config.yaml` с проверкой и откатом.

## Как это устроено

```
                      ┌───────────────────────────── run.py ─────────────────────────────┐
 RTSP-камера ───────► │ Camera (поток чтения, всегда свежий кадр, автопереподключение)    │
                      │        │                                                         │
                      │        ▼                                                         │
                      │ AccessService (src/service.py)                                   │
                      │   ├─ движок распознавания (ArcFace): лица → id сотрудника        │
                      │   ├─ зоны турникета: вход / выход                                │
                      │   ├─ открытие турникета через API Perco  ◄──────────────┐        │
                      │   ├─ журнал проходов (Perco + локальный events.jsonl)    │        │
                      │   └─ RTSPStreamer (ffmpeg) ──► MediaMTX ──► WebRTC ──► браузер    │
                      │                                                          │        │
                      │ FastAPI (main.py) + WebGuard (вход, права, IP)           │        │
                      └──────────────────────────────────────────────────────────┼────────┘
                                                                                 ▼
                                                                          Perco (API)
```

**Поток обработки кадра.** Поток чтения кадров всегда держит последний кадр. Цикл распознавания берёт кадр, уменьшает его (`reduce_frame`),
ищет лица, сопоставляет с эмбеддингами и смотрит, стоит ли распознанное лицо в одной из зон. Если стоит, и с прошлого прохода этого человека
прошло больше `min_time_diff` секунд, отправляется команда открытия турникета в нужную сторону, сохраняется снимок и пишется событие.

**Журнал «кто входил и выходил».** Основной источник: журнал событий Perco (`/api/eventsystem`), откуда читаются проходы за сегодня
(карты, лицо, кнопка вахтёра). Пока Perco недоступен, страница показывает проходы по лицу, которые распознала эта камера (локальный журнал).

## Установка

### Системные пакеты (Ubuntu)

```bash
sudo apt install python3 python3-pip ffmpeg openssl fonts-dejavu-core
```

- `ffmpeg`: публикация видео в MediaMTX (для NVENC нужна сборка с поддержкой `h264_nvenc` и драйвер NVIDIA).
- `openssl`: самоподписанный сертификат для HTTPS.
- `fonts-dejavu-core`: шрифт для кириллических подписей на кадре (`camera.FONT_PATH_RUS`).

### Python-пакеты

Список составлен по импортам кода; сверьтесь со своим `requirements.txt`, если он есть.

```
numpy  opencv-python  pillow  pyyaml  requests  httpx  pandas  openpyxl
fastapi  uvicorn  python-multipart
insightface  onnxruntime-gpu
```

> **Важно про onnxruntime.** Для работы на видеокарте должен стоять **только** `onnxruntime-gpu`, обычный `onnxruntime` рядом с ним нужно удалить.
> Нужны совместимые CUDA и cuDNN. Проверка:
> `python3 -c "import onnxruntime as o; print(o.get_available_providers())"`: в списке должен быть `CUDAExecutionProvider`.
> В логе при запуске строка `GPU requested, but some models run on CPU` означает, что распознавание работает на процессоре (медленно, порядка 3 кадров/с).

### MediaMTX

Нужен для просмотра видео в браузере. Поставьте его на этот же компьютер. В `rtsp_server.url` указывается адрес публикации
(`rtsp://127.0.0.1:554/test`), в `webrtc.api` порт WebRTC (`http://127.0.0.1:8889`). Страница не ходит в MediaMTX напрямую: запрос идёт через
`POST /webrtc/whep/<путь>` на самой программе (так работают тот же адрес и тот же HTTPS).

## Запуск и пароль Perco

Пароль учётной записи Perco (`connection.login`, обычно `api`) **не хранится в `config.yaml`**, а передаётся при запуске.

```bash
python3 run.py ПАРОЛЬ            # веб-интерфейс + распознавание
python3 run.py --encode ПАРОЛЬ   # только посчитать эмбеддинги для фото из images_folder
python3 run.py --list ПАРОЛЬ     # вывести список пользователей и сохранить Id_for_tele.xlsx
python3 run.py --hash-password   # хеш пароля для аварийных учёток (auth.users), пароль Perco не нужен
```

Пароль можно передать и переменной окружения `FACE_PERCO_PASSWORD`, тогда аргумент не нужен. Если заданы оба, главнее аргумент запуска.
Если пароль не передан вовсе, программа напишет «не задан пароль Perco» и не запустится.

Другие переменные окружения: `FACE_CONFIG` задаёт путь к конфигу (по умолчанию `configs/config.yaml`).

### Автозапуск (systemd)

`/etc/systemd/system/faceid.service`:

```ini
[Unit]
Description=Face Access
After=network-online.target
Wants=network-online.target

[Service]
WorkingDirectory=/faceId
ExecStart=/usr/bin/python3 /faceId/run.py ПАРОЛЬ
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now faceid
journalctl -u faceid -f          # живой лог
```

> **Пароль в командной строке виден** в `ps` и `systemctl status` всем локальным пользователям. Надёжнее вынести его в файл с правами 600:
>
> ```ini
> [Service]
> EnvironmentFile=/etc/faceid.env             # внутри одна строка: FACE_PERCO_PASSWORD=ПАРОЛЬ
> ExecStart=/usr/bin/python3 /faceId/run.py
> ```
>
> ```bash
> sudo chmod 600 /etc/faceid.env
> ```

### Первый запуск

1. Положите `config.yaml` в `configs/`, пропишите `connection.host`, `connection.login`, адрес камеры и зоны турникета.
2. Запустите. HTTPS-сертификат создастся сам (для адресов из `web.cert_ips`, `rtsp_server.url` и `127.0.0.1`).
3. Откройте `https://<адрес-сервера>:8000`, подтвердите исключение для самоподписанного сертификата и войдите учётной записью Perco.
4. На вкладке «Сотрудники и фото» подготовьте фото, на вкладке «Конфиг → Настройки» нажмите «Синхронизировать».

Каждый запуск (и перезапуск после смены конфига) отделяется в `log.txt` строкой из знаков `=`.

## Настройка: config.yaml

Конфиг проверяется при загрузке и при сохранении на странице. Если он некорректен, остаётся прежний (копия `config.yaml.bak`).

### Источник пользователей и общие параметры

| Параметр | Значение |
|---|---|
| `source` | `db`: сотрудники из Perco; `excel`: из файла `excel_file` (столбцы `[ID, Имя]`) |
| `excel_file` | файл для `source: excel` |
| `images_folder` | папка с фото сотрудников, файлы `<id>.jpg` |
| `no_name_user` | подпись для неопознанного лица (например `не_узнал`) |
| `date_time_format` | формат даты и времени для имён файлов снимков |
| `log_file` | файл журнала (по умолчанию `log.txt`, ротация 5 МБ × 5 файлов) |
| `log_view_hours` | **за сколько последних часов показывать журнал на вкладке «Журнал»** (1–720, по умолчанию 6) |
| `events_file` | локальный журнал проходов по лицу (`events.jsonl`); пусто: только в памяти |
| `events_keep` | сколько последних проходов хранить в `events_file` (500) |
| `test_mode` | `True`: турникет **не открывается**, события только в журнале (для проверки без риска) |

### Движок распознавания

```yaml
mode: arcface                 # имя движка (src/engines/)

arcface:
  model_name: buffalo_l       # buffalo_l (точнее) / buffalo_s (быстрее)
  embedding_folder: arcface_embeddings
  threshold: 0.45             # косинусное сходство: чем ВЫШЕ, тем строже
  det_thresh: 0.5             # минимальная уверенность детектора лиц
  det_size: [640, 640]        # вход детектора; больше - лучше видит мелкие лица, но медленнее
  cpu_threads: 2
```

Для режима `mode: X` обязателен одноимённый раздел `X:` с `embedding_folder` и `threshold`.

### API Perco

```yaml
connection:
  host: 192.168.0.15
  login: api
  # password здесь НЕТ: передаётся при запуске (см. «Запуск и пароль Perco»)
  # all_users_query: {имя_параметра: значение}   # если запрос списка сотрудников без параметров отдаёт не всех
```

Учётная запись `connection.login` должна иметь в Perco право читать сотрудников, подразделения, журнал событий и менять карточки сотрудников
(отметка «проход по лицу»), а также открывать турникет.

### Камера и турникет

```yaml
camera:
  id: rtsp://192.168.0.46/ONVIF/MediaInput?profile=3_def_profile3   # RTSP или номер USB-камеры (0)
  rtsp_transport: tcp         # tcp | udp (пусто: по умолчанию ffmpeg)
  reduce_frame: 2             # во сколько раз уменьшать кадр для поиска лиц
  frame_mode: center          # center: центр лица в зоне; full: лицо целиком в зоне
  frame_folder: frame         # снимки срабатываний
  frame_keep_days: 14         # снимки старше N суток удаляются (0: не удалять)
  EXIT: Выход                 # подписи зон на кадре
  ENTRANCE: Вход
  FONT_PATH_RUS: /usr/share/fonts/truetype/dejavu/DejaVuSans.ttf

turnstiles:
  area_1: [0.09, 0.0, 0.17, 1.0]   # ВЫХОД: x, y, w, h (доли кадра)
  area_2: [0.34, 0.0, 0.2, 1.0]    # ВХОД
  id_tur: 3                        # id контроллера турникета в Perco
  min_time_diff: 6                 # не чаще раза в N секунд для одного человека
  face_pass_field_id: -4           # id поля карточки сотрудника в Perco с отметкой «проход по лицу»
```

- Зоны задаются в долях кадра: `[x, y, ширина, высота]`, значения 0–1. Они рисуются на видео.
- `frame_mode: center` удобнее, когда человек стоит на границе зоны; `full` строже.
- Без `FONT_PATH_RUS` кириллические имена на кадре заменяются на `ID <номер>`.

### Журнал событий Perco (необязательный блок)

```yaml
perco_events:
  enabled: true                               # false: показывать только проходы по лицу с этой камеры
  poll_sec: 5                                 # как часто читать журнал Perco
  pass_event_ids: [17]                        # какие события считать проходами (17 = «Проход по идентификатору»)
  outside_zone_id: 1                          # id зоны «Неконтролируемая территория»
  remote_event_id: 112                        # «Проход по команде от ДУ» (кнопка вахтёра)
  reader_directions: {1: entrance, 2: exit}   # номер считывателя -> направление для проходов по кнопке
  # login: "..."                              # отдельная учётка только на чтение журнала (если у connection.login нет права)
  # password: "..."
```

Все ключи необязательны, значения по умолчанию приведены выше. Ключ `perco_events` в файле должен быть **один**: повторный ключ в YAML молча перекрывает первый.

### Трансляция в MediaMTX

```yaml
rtsp_server:
  enabled: true
  url: "rtsp://127.0.0.1:554/test"
  width: 1280
  height: 720
  fps: 25
  encoder: auto               # auto | nvenc | x264
  bitrate: 3M

webrtc:
  api: http://127.0.0.1:8889
```

`encoder: auto` проверяет NVENC реальным тестовым кодированием; если не работает, берётся `libx264` (процессор).

### Вход в веб-интерфейс

```yaml
auth:
  enabled: true               # false: вход не нужен (не рекомендуется)
  provider: perco             # perco | local (пользователи из auth.users)
  allowed_logins: []          # допущенные учётки Perco; пусто = любая, которую примет Perco
  session_hours: 12           # сколько действует вход
  max_attempts: 5             # неверных попыток с одного IP ...
  max_attempts_per_login: 10  # ... или для одного логина (с любых адресов) ...
  lockout_minutes: 10         # ... и блокировка на столько минут
  # roles: {"Вахта": 1}       # свои роли Perco -> уровень доступа 1..3 (см. «Вход и права доступа»)
  # users:                    # аварийные учётки, действуют только пока Perco недоступен
  #   - login: "admin"
  #     password_hash: "pbkdf2_sha256$..."
  #     level: 3              # необязательно, по умолчанию 3
```

### Веб-сервер

```yaml
web:
  host: 0.0.0.0
  port: 8000
  ssl: true                   # HTTPS нужен, чтобы браузер дал доступ к веб-камере (для фото)
  cert_ips: [192.168.0.200, 192.168.0.6]   # IP сервера для самоподписанного сертификата
  allowed_ips: []             # кто может открыть страницу, напр. ['192.168.0.10', '192.168.0.0/24']; пусто = все
```

Свой сертификат: положите `certs/cert.pem` и `certs/key.pem` (или задайте `web.ssl_cert` и `web.ssl_key`). Если файлов нет, создаётся самоподписанный на 825 дней.

## Веб-интерфейс

Страница одна, у неё три вкладки; какие из них видны, зависит от роли ([права доступа](#вход-и-права-доступа)).

### 1. Камера и проходы

- **Видео** с зонами «Вход» и «Выход» и подписями лиц. Видео можно выключить (кнопка): тогда страница не тянет поток, а таблица проходов занимает освободившееся место.
- **Строка статуса** в одну строку: состояние сервиса, камера, кадров/с, режим, число сотрудников, число проходящих по камере, число эмбеддингов, кодек.
- **Последний вошедший или вышедший** крупно рядом с заголовком «Кто входил и выходил»: направление, имя, время.
- **Таблица проходов**: время, сотрудник, подразделение, направление, способ (карта, лицо, кнопка вахтёра, команда оператора).
- **Фильтры**: поле «Фамилия или имя» (без учёта регистра, «е» = «ё») и выпадающий список подразделений. Подразделения берутся из самих проходов.
- **Только в здании сейчас**: показывает людей, чей последний проход за сегодня был входом. Рядом счётчик и оценка с учётом кнопки.
- Подпись рядом со счётчиком показывает источник данных (журнал Perco или только локальные проходы) и причину, если журнал Perco недоступен.

### 2. Сотрудники и фото

- **Список сотрудников** с поиском и фильтром по подразделению (плоский список, без иерархии, «Все подразделения» по умолчанию) и флажком «только с выключенным проходом».
- **Метки в списке:**
  - `✓` — есть эмбеддинг (фото обработано);
  - `⛔` — проход по лицу выключен (оранжевая строка): по камере не пройдёт;
  - `⚠` на красном фоне — проход по лицу **включён, а эмбеддинга нет**: камера такого сотрудника не узнает, нужно фото или синхронизация.
  Расшифровка вынесена под список вместе с числом сотрудников.
- **Фото**: веб-камера компьютера (кнопка «Включить камеру», при двух и более камерах появляется выбор камеры, выбор запоминается) или файл. Снимок делается кнопкой «Снять» или **двойным кликом по видео**.
- **Кнопки управления**: «Сохранить фото», «Включить проход по лицу», **имя выбранного сотрудника между кнопками**, «Убрать проход по лицу».
- Веб-камера браузера работает только по HTTPS (или на `localhost`).

### 3. Конфиг

Две подвкладки, по умолчанию открывается **«Журнал log.txt»**.

- **Журнал log.txt**: записи за последние `log_view_hours` часов, свежие внизу. Предупреждения выделены жёлтым, ошибки красным. Есть кнопка «Обновить» и флажок «только предупреждения и ошибки». Учитываются архивные `log.txt.1`, `log.txt.2` ...
- **Настройки**: редактор `config.yaml`. «Применить» проверяет конфиг и перезапускает распознавание на несколько секунд; при ошибке остаётся прежний. Можно загрузить файл `config.yaml` целиком. Кнопка «Синхронизировать» перечитывает список сотрудников и считает эмбеддинги для новых фото.

## Вход и права доступа

Логин и пароль на странице входа проверяет **Perco**: данные отправляются в Perco тем же запросом, которым программа входит в него.
Perco выдал токен — человек вошёл. Паролей в `config.yaml` нет. Сессия хранится в куке `fa_session` (HttpOnly, SameSite=Strict, Secure по HTTPS).

После успешного входа программа определяет **роль оператора** в Perco (`/api/users/operators/table`) и по ней уровень доступа:

| Роль в Perco | Уровень | Доступные вкладки |
|---|---|---|
| `Уровень1` | 1 | Камера и проходы |
| `Уровень2` | 2 | Камера и проходы, Сотрудники и фото |
| `Уровень3`, `admin` | 3 | все три вкладки |

- Оператор не найден в списке, **заблокирован** (`is_block`) или имеет другую роль: вход закрыт, на странице входа объяснение причины.
- Свои роли добавляются в конфиге: `auth.roles: {"Вахта": 1}`.
- Если список операторов получить не удалось, вход закрыт («не удалось определить роль»). Это сделано намеренно.
- Роль определяется **при входе** и действует до конца сессии (`session_hours`). Изменили роль в Perco: новые права после повторного входа.
- Аварийные учётки (`auth.users`, только пока Perco недоступен) и режим `provider: local` получают уровень 3, либо значение поля `level`.
- `allowed_logins` работает поверх ролей: если список задан, войдут только перечисленные.

**Права проверяются на сервере**, а не только скрытием вкладок:

| Уровень | Адреса |
|---|---|
| 1 | `/`, `/static/*`, `/api/status`, `/api/events`, `/webrtc/whep/*` |
| 2 | + `/api/users`, `/api/divisions`, `/api/photo`, `/api/enable-pass`, `/api/disable-pass` |
| 3 | + `/api/config`, `/config`, `/sync`, `/api/log` и всё остальное |

Защита от перебора: после `max_attempts` неверных попыток с одного IP или `max_attempts_per_login` для одного логина вход блокируется на `lockout_minutes` минут.
Дополнительно действует ограничение по IP (`web.allowed_ips`).

## Журнал проходов

### Источники

1. **Журнал событий Perco** (`GET /api/eventsystem?beginDatetime=...&endDatetime=...`), читается каждые `poll_sec` секунд.
   При первом чтении берутся сутки целиком (данные появляются на странице уже после первой страницы ответа, пока идёт загрузка, на странице так и написано),
   дальше только свежий хвост. Новые сутки начинаются с нуля.
2. **Локальный журнал** (`events.jsonl`): проходы по лицу, которые распознала эта камера. Используется, пока журнал Perco недоступен.

### Как разбираются события Perco

| Событие | Что это | Как используется |
|---|---|---|
| 17 «Проход по идентификатору» | проход по карте или лицу | запись в таблице. Направление: пришёл из зоны `outside_zone_id` = вход, ушёл в неё = выход. Способ: нет идентификатора = лицо, есть = карта |
| 112 «Проход по команде от ДУ» | турникет провернулся по кнопке вахтёра | запись «Вахтёр (кнопка)». Направление по считывателю события: № 1 = вход, № 2 = выход (`reader_directions`) |
| 16010 «Открыть ИУ: Выполнено» | команда открытия | если команду дала другая учётка в пределах 5 с от события 112, строка помечается «Оператор: логин» |
| 117, 118, 5205 | разблокировка/блокировка ИУ, ожидание прохода | служебные, в таблицу не попадают |

### «Только в здании»

Для каждого человека (по `user_id`) берётся его **последний проход за сегодня**; если это вход, он «в здании».
Проходы по кнопке не содержат сведений о человеке, поэтому в этот список не входят, но учитываются в общей оценке:

```
всего примерно = (по идентификатору в здании) + (вошло по кнопке) − (вышло по кнопке)
```

Оценка корректна, пока в здании никого не остаётся на ночь (вечером всех выводят) и счёт идёт с начала суток.
Если человек вошёл по карте, а вышел по кнопке, список «по идентификатору» его не уберёт, а оценка это учтёт.

### Ограничения

- Время и «сутки» считаются по часам компьютера, где запущена программа. Часовой пояс должен совпадать с Perco.
- Постраничное чтение журнала использует параметр `page` и поле `total` ответа. Если у вашей версии Perco постраничность устроена иначе, проходы за большой день могут быть неполными.
- В таблицу без фильтра попадают последние 300 проходов, с фильтром до 3000 (чтобы найти человека за весь день).

## Сотрудники, фото и проход по лицу

- **Источник сотрудников**: `source: db` (Perco) или `excel`. Камерой распознаются только сотрудники с включённой отметкой «проход по лицу»
  (поле карточки с id `face_pass_field_id`); на вкладке «Сотрудники и фото» видны все.
- **Фото** хранятся как `images/<id>.jpg`. По фото считается эмбеддинг (файл в `arcface_embeddings/`). Фото, на котором лицо не найдено, эмбеддинг не даст.
- **Включить проход по лицу**: считает эмбеддинг по новому фото (или использует готовый) и ставит отметку в карточке сотрудника в Perco.
- **Убрать проход по лицу**: фото и эмбеддинг уходят в архив, отметка в Perco снимается.
- **Синхронизировать**: перечитывает сотрудников из источника и досчитывает эмбеддинги для новых фото. Показывает сколько обработано и сколько фото без лица.
- **Подразделения**: список из `GET /api/divisions/list` (удалённые пропускаются); принадлежность сотрудника берётся из списка сотрудников, при отсутствии из карточек.
  Список подразделений публикуется сразу, принадлежность сотрудников догружается в фоне, пока счётчики в скобках могут показывать 0.

Командные ключи для работы без веба: `python3 run.py --encode ПАРОЛЬ`, `python3 run.py --list ПАРОЛЬ`.

## Видео и MediaMTX

Программа кодирует кадры с разметкой и публикует их в MediaMTX по RTSP через `ffmpeg`; браузер получает их по WebRTC.

- **Кодек**: `h264_nvenc` (видеокарта) или `libx264` (процессор). При `encoder: auto` NVENC проверяется реальным тестовым кодированием.
  Если полный набор параметров не подошёл, пробуются упрощённые (старые драйверы, другая сборка ffmpeg). Если не работает совсем, берётся `libx264`.
- **Не блокирует распознавание**: очередь на 2 кадра, при переполнении старый кадр выбрасывается.
- **Переподключение**: при недоступном MediaMTX пауза между попытками растёт до 10 секунд, лог не засоряется.
- **Ключевой кадр** раз в секунду (`-g = fps`): зритель не ждёт.
- **Остановка**: ffmpeg останавливается с ожиданием завершения, чтобы не держать сессию NVENC при перезапуске.
- **Камера**: чтение RTSP в отдельном потоке с таймаутами открытия и чтения 5 секунд и автопереподключением. Нет сигнала: на видео надпись «Нет сигнала с камеры».

## Журнал log.txt

Формат строки: `04/11/26 10:19:55 INFO face_access.service: Starting: ...` (дата `дд/мм/гг`, время, уровень, модуль, сообщение).
Ротация: 5 МБ × 5 файлов. Каждый запуск отделяется строкой из `=`. Тот же журнал выводится в консоль (`journalctl -u faceid`).

Основные сообщения:

| Сообщение | Что значит |
|---|---|
| `Starting: mode=arcface source=db test_mode=False` | запуск сервиса |
| `Embeddings loaded: N of M users` | загружено эмбеддингов (из М сотрудников, проходящих по камере) |
| `Service started: N users recognized by camera (M in total)` | сервис готов |
| `Camera connected` / `Camera not available: ...` | состояние камеры; при сознательной остановке пишется `Camera released` |
| `Perco events: loading today's journal...` / `N passes loaded` | первое чтение журнала событий |
| `Cannot read Perco events: ...` | журнал событий недоступен (подробности в разделе «Диагностика») |
| `Divisions loaded: N` / `Employee divisions loaded: N of M` | подразделения загружены |
| `RTSP encoder: libx264` / `h264_nvenc` | выбранный кодек трансляции |
| `Web login: <логин> (perco) from <IP>` | вход на страницу |
| `Manual door open ...` | проход по кнопке с направлением и соседними событиями |

## Диагностика

### Журнал проходов пустой, в подписи «журнал Perco недоступен»

В подписи рядом со счётчиком и в `log.txt` (`Cannot read Perco events: ...`) указана причина.

- **403 Forbidden**: у учётки `connection.login` нет права на журнал событий. Дайте право в Perco или задайте отдельную учётку на чтение в `perco_events.login` и `perco_events.password`.
  Проверка: `python3 check_events.py configs/config.yaml` (пароль из `FACE_PERCO_PASSWORD` или запрос с клавиатуры).
- Список событий за N минут (чтобы увидеть, что пишет Perco при нажатии кнопки): `python3 check_events.py configs/config.yaml 10`.
- **Connection reset by peer**: Perco закрыл простаивающее соединение. Запрос автоматически повторяется до двух раз; в логе остаётся строка, только если все повторы не помогли.
- Журнал загружается долго: смотрите подпись «идёт загрузка за сегодня...»; данные появляются по мере чтения страниц.

### Проход по кнопке без направления

В таблице «проход» без стрелки: у события нет известного считывателя. Строка `Manual door open ... direction=...` в логе содержит соседние события:
пришлите её, при необходимости поправьте `perco_events.reader_directions` и `remote_event_id`.

### Распознавание медленное, `GPU requested, but some models run on CPU`

Распознавание работает на процессоре. Проверьте, что установлен только `onnxruntime-gpu` и доступен `CUDAExecutionProvider`
(команда в разделе «Установка»), совместимость CUDA и cuDNN (`python3 check_gpu.py`).

### `NVENC test failed`

Трансляция продолжает работать на `libx264`. В логе записан полный текст ошибки ffmpeg: по нему видно причину (драйвер, лимит одновременных сессий NVENC, версия NVENC API).
Частая причина после перезапуска: старый ffmpeg ещё держал сессию видеокарты; программа теперь дожидается его завершения и пробует упрощённые параметры.

### Вход на страницу

- «Perco не принял вход»: неверные логин или пароль учётки Perco.
- «Роль не допущена к веб-интерфейсу»: роль оператора не из списка (`Уровень1/2/3`, `admin`); добавьте её в `auth.roles`.
- «не удалось определить роль оператора»: недоступен `/api/users/operators/table` (нет права у `connection.login` или Perco не отвечает).
- «Слишком много неудачных попыток»: блокировка на `lockout_minutes` минут.
- Пока раздела `auth` нет, веб-интерфейс закрыт целиком (распознавание и турникет при этом работают).

### Веб-камера в браузере не включается

Нужен HTTPS или `localhost` (`web.ssl: true`), в браузере разрешён доступ к камере. При нескольких камерах выберите нужную в списке рядом с кнопкой «Включить камеру».

### Программа не запускается: «не задан пароль Perco»

Передайте пароль при запуске (`run.py ПАРОЛЬ`) или переменной `FACE_PERCO_PASSWORD`. Строку `password` в `config.yaml` можно не держать.

### Проверка без риска

`test_mode: True` в `config.yaml`: распознавание и журнал работают, а турникет не открывается.

## Безопасность

- **Пароль Perco** не хранится в репозитории и в `config.yaml`: передаётся при запуске. Он виден в `ps`; для защиты используйте `EnvironmentFile` с правами 600.
- **`.gitignore`** исключает `configs/config.yaml`, `.env`, сертификаты и ключи, `images/`, `arcface_embeddings/`, `frame/`, `archive/`, `*.xlsx`, журналы. В репозитории держите `configs/config.example.yaml` без секретов.
  Если `config.yaml` уже был в git: `git rm --cached configs/config.yaml`, а прежние пароли и токены Perco считайте скомпрометированными и замените.
- **Фото и эмбеддинги**: биометрические данные, в репозиторий и во внешние сервисы не передавать.
- **Страница**: вход по учётной записи Perco, роли, блокировка перебора, ограничение по IP, заголовки безопасности (`X-Frame-Options: DENY`, `nosniff`, `no-store`).
  Автодокументация FastAPI (`/docs`) отключена. Имена сотрудников выводятся на страницу только как текст (не HTML).
- **HTTPS**: самоподписанный сертификат подходит для локальной сети; браузер при первом входе попросит подтвердить исключение.
